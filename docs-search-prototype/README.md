# Docs Search Prototype

Прототип **мгновенного клиентского поиска** по локальным XHTML-статьям.

Поиск работает полностью в браузере (Fuse.js). После загрузки индекса задержка обычно составляет 1–5 мс даже на слабых машинах.

## Что внутри

```
docs-search-prototype/
├── data/                  ← сюда кладёте свои .xhtml файлы
├── public/
│   ├── index.html         ← страница поиска
│   └── search-index.json  ← генерируется индексатором
├── indexer.py             ← скрипт индексации
├── requirements.txt
└── README.md
```

## Быстрый старт

### 1. Положите статьи

Скопируйте ваши 70 (или любое количество) `.xhtml` / `.html` файлов в папку `data/`:

```bash
cp /path/to/your/articles/*.xhtml ./data/
```

Имена файлов будут использоваться как ID (например `123456.html` → id = `123456`).

### 2. Установите зависимости Python

```bash
cd docs-search-prototype
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Постройте индекс

```bash
python indexer.py
```

Скрипт:
- прочитает все `.xhtml` / `.html` из `data/`
- извлечёт title, текст, заголовки
- сохранит компактный JSON в `public/search-index.json`

Чтобы ссылки в результатах поиска открывали исходные файлы, скопируйте статьи в `public/data/`:

```bash
mkdir -p public/data
cp data/*.xhtml public/data/   # или cp data/* public/data/
```

Пример вывода:
```
Найдено файлов: 70
  [1/70] 123456.xhtml
  ...
Успешно проиндексировано: 70 документов

Индекс сохранён: public/search-index.json (842.3 KB)
```

### 4. Запустите локальный сервер и откройте поиск

**Важно:** браузер не даёт `fetch` работать через `file://`. Нужен любой простой HTTP-сервер.

Самый простой способ:

```bash
cd public
python -m http.server 8000
```

Затем откройте в браузере:

```
http://localhost:8000
```

Готово. Начинайте вводить запрос — результаты появляются мгновенно.

## Как пользоваться поиском

- Вводите любые части слов: `ing`, `tls`, `ns`, `restore`, `pod`
- Работает нечёткий поиск (опечатки, частичные совпадения)
- Результаты кликабельны — открывают исходный `.xhtml` файл
- В карточке результата показывается ID файла, примерный размер и score

## Что делает индексатор (этапы)

1. **Чтение** всех `.xhtml`/`.html` из `data/`
2. **Парсинг** (BeautifulSoup + lxml/html5lib)
3. **Извлечение**:
   - title (`<title>` → `<h1>` → fallback на имя файла)
   - полный текст (без script/style/nav)
   - заголовки h1–h4
   - простой список aliases из слов заголовка
4. **Нормализация** пробелов
5. **Ограничение** размера `content` (чтобы индекс не раздувался)
6. **Сериализация** в один JSON-файл

Это упрощённый, но рабочий черновик пайплайна из архитектурного документа.

## Настройки поиска (можно менять)

В `public/index.html` найдите объект `FUSE_OPTIONS`:

```js
threshold: 0.38,        // чем меньше — тем строже
keys: [
  { name: "title",    weight: 0.45 },
  { name: "aliases",  weight: 0.25 },
  { name: "headings", weight: 0.15 },
  { name: "content",  weight: 0.10 },
  ...
]
```

Можно добавлять новые поля в индекс (в `indexer.py`) и сразу использовать их в `keys`.

## Обновление индекса

После изменения статей в `data/`:

```bash
python indexer.py
```

Обновите страницу в браузере (или сделайте hard-refresh).

## Ограничения прототипа

- Нет словаря синонимов и аббревиатур (svc → service и т.д.) — это следующий шаг
- Нет полноценного intent-ранжирования
- Нет подсветки внутри длинного content (только title)
- Индекс содержит урезанный `content` (первые ~8000 символов) — для 70–3000 статей этого обычно достаточно

Эти ограничения легко снимаются в следующих итерациях, сохранив ту же схему «индексатор → JSON → клиентский поиск».

## Дальнейшее развитие (по архитектурному документу)

1. Добавить curated synonym + abbreviation словари
2. Character n-gram / более умный tokenizer
3. Metadata boosting (популярность, категория)
4. Multi-stage ranking
5. Опционально — лёгкие embeddings
6. Переход на более компактный бинарный формат индекса при росте корпуса

---

Если что-то не работает — проверьте:
- файлы действительно лежат в `data/`
- `python indexer.py` отработал без ошибок
- вы открываете страницу через `http://localhost:8000`, а не как файл
